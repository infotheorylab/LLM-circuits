With hundreds of models to choose from, which ones should we use?

An LLM classifier is a noisy measurement instrument

Two models can give different answers to the same question, and so can one model asked twice. Every answer costs money.

We treat each model, with its prompt and settings, as an instrument: each call is a noisy measurement of the true label, at a price.

We call the combination of LLM classifiers a circuit

Combining classifiers is a classic problem in machine learning. Each LLM classifier runs on its own hardware, so we call their combination a circuit.

Majority voting, routing and cascades are circuits, and so is LMCircuit, the method of this paper. They differ in which models they ask, in what order, and how they turn the answers into one prediction.

A circuit decides which model to query next and when to stop

After each answer, the circuit either asks another model or stops and predicts. If we care about cost, asking one model at a time loses nothing.1

1 If we care about speed, asking several models in parallel is faster.

The best circuit is the solution of a dynamic program

Each answer changes what the next call is worth, so the choices form a tree. The dynamic program finds the best tree by working backward from the predictions.

It weighs the cost of one more answer against how much that answer lowers the chance of a mistake. Prioritize accuracy and the circuit asks more. Prioritize cost and it asks less.

Any circuit gets better with a little routing

Prompts differ in difficulty. Some are easy for every model and others split them, so one plan for every prompt wastes money.

LMCircuit adds a small prompt classifier. It reads the prompt and predicts the label and which models will get it right. It trains in minutes and runs on a CPU.

LMCircuit is a prompt classifier and a dynamic program

We fit the prompt classifier once. For any setting, from prioritize cost to prioritize accuracy, the dynamic program turns its estimates into a circuit.

The prompt classifier reads a text embedding of the prompt (Qwen3-Embedding-0.6B) and the answers collected so far. It returns the chance the prompt is harmful and the chance each model gets it right. It is trained on labelled prompts and recorded model answers.

LMCircuit achieves higher accuracy at nearly every budget

It is more accurate than every single model and than eight routing and cascading methods. Here are five of the seven tasks: four judged by open-weight models and one by decision models.

Circuits of LLM Classifiers

Abstract. Language models make it easy to build classifiers by simply prompting a model with the sample to classify. However, their predictions are neither deterministic nor uniformly reliable across samples. How can we combine predictions from different models to improve reliability? We view LLM classifiers as noisy measurement instruments of an underlying target label. Our goal is to maximize average classification accuracy at a given average query cost. To this end, we introduce circuits that organize LLM classifiers into an adaptive sequence of queries and decisions. We then characterize the optimal circuit, obtain the fundamental limits of achievable accuracy, and provide practical insights on realizing the optimal circuit. Across seven classification tasks spanning safety, health, political science, human preference, agent evaluation, decision-making and reasoning, our method improves the cost–accuracy frontier over routing and cascading baselines.

Technical details

For a prompt z, a state s is the set of (instrument, answer) pairs observed so far. The belief is qz(s) = P(Y = 1 | z, s) and the stopping error is ez(s) = min{qz(s), 1 − qz(s)}. With a price λ on cost, the value of a state satisfies

01

Sequential without loss. Any circuit that queries a batch of instruments at once has a sequential counterpart with the same error and cost, so the search can be restricted to one query at a time.

02

Conditional independence. Each call uses fresh randomness, so we model answers as independent given the prompt. Errors can still be correlated across prompts, and the embedding captures this. Without seeing test labels, the fitted model predicts the correlations between instruments' answers, and between their errors, to within 4% of the measured values on six tasks (15–17% low on BIG-Bench Hard, the smallest). It predicts each instrument's accuracy to within 1.2 to 3.6 points.

03

Belief model (the prompt classifier). fθ(φ(z), s) = (ηθ(φ(z), s), νθ(1)(φ(z), s), …, νθ(n)(φ(z), s)). A learned projection of a 1024-dimensional Qwen3-Embedding-0.6B vector to 64 dimensions feeds three small heads. The model assumes each prompt belongs to one of T latent types: a type head gives the prior over types, a measurement head gives each instrument's chance of answering 1 under each type, and a label head gives the label probability under each type at state s, summing learned embeddings of the observed (instrument, answer) pairs so it is invariant to their order. The observed answers update the type by Bayes' rule and the outputs average over types. T ∈ {1, 2, 4, 8} is chosen on validation.

04

Loss. For each training prompt we draw a random state (a random subset of instruments and one recorded answer each) and minimize binary cross-entropy of η against the recorded labels, weighted by annotator counts where several annotators labeled a prompt (as on HealthBench), plus cross-entropy of each unqueried νi against every recorded call of instrument i. AdamW with early stopping on validation; one temperature for the label and one for the instruments' answers is then fit on validation states; five seeds per fold.

05

Costs. ci(z) is known before the query. On the four tasks we query ourselves it is the input tokens of z times the input price, plus the 95th percentile of the instrument's output length on training prompts times the output price. On AgentJudgeBench, BIG-Bench Hard and Decision Index it is the instrument's mean cost on training prompts, priced as in the data sheet (these benchmarks recorded no call costs). Costs are divided by the mean cost of the most expensive instrument.

06

Frontier. The dynamic program is solved for 201 prices spaced geometrically from 10−8 to 102, plus λ = 0 and λ = ∞. Each dataset is split into five folds, keeping prompts that share a source together. For each budget the price with the best validation balanced accuracy within budget is selected and its test balanced accuracy reported.

07

Pool selection. The drop in the lowest achievable error from adding an instrument is at most √(I(Y; Xnew | Xpool, Z)/2). Starting from a cheap instrument and greedily adding the one with the largest conditional information reaches the full-pool frontier with 2–3 instruments on the four tasks where we query the models ourselves, and dominates accuracy-first, cheapest-first and random orderings.

08

Scaling laws. For one prompt, the error of the best circuit falls exponentially with the amount spent, −log Eλ(z) / Cλ(z) → I(z), where I(z) is the largest information per unit cost among the models (the KL divergence between a model’s answers under the two labels, divided by its cost). The circuit then spends almost all of its budget on that model. Averaged over prompts, the error falls more slowly when many prompts are hard for every model.

Baselines

Predictive routers pick one model per prompt. Cascades ask models one after another until a confidence rule fires. Sampling asks one model again and again until its answers agree. All are circuits. Routers and cascades over the same models are among the circuits the dynamic program compares.
